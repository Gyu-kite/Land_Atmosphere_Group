## 1. 연구 배경과 반복 작업 선택

### 1.1 연구 소개

본 연구는 NASA Land Information System Framework(LISF)를 이용해 위성
토양수분을 지면모델에 동화하는 연구이다. 단일모델 EnKF와 여러 지면모델의
ensemble을 결합하는 Multi-Model Data Assimilation(MMDA)을 비교한다.
주요 검증 자료는 International Soil Moisture Network(ISMN)의 지상 토양수분이다.

자료동화 실험을 추가하거나 평가 기준을 변경할 때마다 공통 날짜와 관측 자료를
확인하고, 성능 지표를 계산하며, 그림과 해석을 수정한다. 이 과정에서
비교 조건의 불일치나 그림 표기의 문제가 반복적으로 발견되었다.

과제에서 지정한 연구 소개 재료는 2주차에 작성한 README.md이다.
현재 저장소 루트 README.md는 multi-source DA와 LNETF 중심의 소개이므로,
이 보고서의 MMDA 소개가 해당 2주차 제출본과 일치하는지는 추가 확인이 필요하다.
아래 후보는 현재까지의 실제 연구 작업과 에이전트 대화에 근거해 작성했다.

### 1.3 후보 1: 자료동화 성능 비교의 정합성 점검

**작업 이름:** 토양수분 자료동화 평가 notebook의 비교 조건 점검

**반복하는 상황:** 새로운 실험을 기존 OL, EnKF, MMDA와 비교하거나,
ACC 계산법과 filtered 기준을 변경했을 때 수행한다.

**입력:** 평가 notebook 또는 Python 코드, 비교 실험의 자료 경로,
ISMN 및 위성 관측 자료의 위치, 사용자가 의도한 평가 기준.

**작업 절차:**

1. 코드가 실제로 읽는 실험과 자료 경로를 확인한다.
2. 실험별 기간 및 실제 공통 평가 날짜를 확인한다.
3. SMAP이 raw인지 scaled인지 확인한다.
4. ACC, ubRMSE, climatology, filtering의 구현을 확인한다.
5. 동일 지표를 사용하는 표와 그림의 표본 수 및 값이 일치하는지 확인한다.
6. 문제를 발견한 위치와 확인 근거를 보고한다.

**출력:** 항목별 `일치 / 불일치 / 확인 불가` 점검표와 코드·자료 위치,
영향받는 비교 결과, 수정 제안. 점검과 실제 코드 수정은 구분한다.

**실제 반복 사례:**

- boxplot과 오차 분해 그림에 표시된 ACC가 서로 달라 계산 정의를 재확인했다.
- 단순 moving mean과 여러 연도의 climatological moving mean을 구분하도록 요청했다.
- raw SMAP 대신 scaled SMAP으로 screening과 그림을 다시 계산하도록 요청했다.
- 위성 관측일의 skill과 모든 날짜의 모델 skill을 같은 비교처럼 취급하지 않도록 했다.

**작업 경계:** 성능이 좋아 보이도록 기준을 바꾸거나, 자료를 확인하지 않고
정상이라고 판정하지 않는다. 기본 작업은 읽기와 점검이며, 모델 실행이나
기존 파일 수정은 별도 요청이 있을 때만 한다.

**정보가 부족한 경우:** 의도한 ACC 정의나 비교 실험을 알 수 없다면
추정하지 않고 질문한다. 코드에서 발견한 사실과 사용자 의도를 구분한다.

**시험 가능성:** 일부러 비교 기간 또는 SMAP 종류가 다른 입력을 주고,
근거를 들어 불일치를 찾는지 확인할 수 있다.

### 1.4 후보 2: 논문 그림의 형식 점검 및 수정

**작업 이름:** 토양수분 성능평가 지도 한 종류의 출판 형식 점검

**반복하는 상황:** 성능 지도나 분산 지도를 다시 그린 뒤, 논문에 사용할
그림의 글자·단위·컬러바·영역을 확인할 때 수행한다.

**입력:** 지도 생성 코드, 생성된 PNG 또는 PDF, 사용자가 정한 그림 규칙.
범위는 지도 한 종류와 그 All/filtered 변형 정도로 제한한다.

**작업 절차:**

1. 원본 그림과 코드의 보존 위치를 정한다.
2. CONUS 표시 영역, label 및 단위, 내부 글자 크기를 확인한다.
3. 컬러바가 지도 높이와 맞는지, 범례와 글자가 겹치거나 잘리는지 확인한다.
4. 허용된 형식 요소만 수정하고 그림을 실제 실행해 저장한다.
5. 이미지를 열어 확인하고 수정 전후의 수치·표본이 변하지 않았는지 점검한다.

**출력:** 수정 그림, 편집 가능한 코드 또는 notebook,
원본 보존 위치, 형식 점검표 및 수치 변경 여부.

**실제 반복 사례:**

- 컬러바 높이가 지도와 맞지 않아 재수정했다.
- 지도 내부 Mean과 N, 지점명이 너무 작아 글자 크기를 키웠다.
- 단위를 `이름 [unit]` 형식으로 맞추고 DA 표기를 아래첨자로 통일했다.
- 비슷한 색의 station network를 다른 색상과 marker로 구분했다.

**작업 경계:** 형식 수정 중 지표, 표본, screening, 지도 데이터를 바꾸지 않는다.
출판 가능 여부는 자동 검사만으로 확정하지 않고 시각 검토를 포함한다.

**시험 가능성:** 작은 글자와 어긋난 컬러바가 있는 지도에 적용하고,
수치 보존과 눈에 보이는 형식 개선을 비교할 수 있다.

### 1.5 후보 3: 오차 분해 그림의 근거 기반 해석 메모

**작업 이름:** CE·VE 오차 분해 그림 한 종류의 결과 해석

**반복하는 상황:** CE, VE, TE 또는 normalized 지표를 이용한 그림을
추가한 뒤, 어느 성분이 개선·악화되었는지 설명할 때 수행한다.

**입력:** 오차 성분 수치표, 해당 그림, 비교 baseline과 차이의 부호 정의,
climatology 및 정규화 정의.

**작업 절차:**

1. CE, VE, TE의 정의와 차이의 부호를 확인한다.
2. 동일 표본에서 TE = CE + VE가 성립하는지 확인한다.
3. 비교 실험 간 각 성분의 평균 변화와 표본 수를 계산한다.
4. 원본과 normalized 결과가 달라 보이는 이유를 분모와 집계 방식에서 확인한다.
5. 확인된 수치, 가능한 해석, 자료만으로 판정할 수 없는 주장을 구분한다.

**출력:** 수치 근거가 포함된 짧은 한국어 해석 메모,
필요한 수식, 영어 caption 초안, 해석상 한계.

**실제 반복 사례:**

- ACC는 좋아졌지만 VE가 악화되는 결과를 분리해서 해석했다.
- normalized 그림에서 결과가 달라 보이는 이유를 재확인했다.
- Delta CE와 Delta ACC의 부호가 반드시 같아야 하는지 확인했다.
- P_inter와 성능의 상관을 곧바로 인과 효과라고 표현하지 않도록 요청했다.

**작업 경계:** 그림에서 보이는 연관성만으로 P_inter의 고유 기여나
최적화된 단일모델보다 우수하다는 결론을 만들지 않는다.
일반적인 논문 전체 작성이나 새로운 알고리즘 설계는 포함하지 않는다.

**시험 가능성:** CE는 개선되지만 VE는 악화되는 수치표를 주고,
TE 변화까지 정확히 계산해 모순 없이 설명하는지 확인할 수 있다.

### 2.1 실제 입력과 요청

실제 사용자 요청은 “그럼 그다음엔 2단계를 해보면 되는건가 ? 2단계를 한번 해봐 그러면”이다.
에이전트는 최근 생성한 월별 SMAP 비교 notebook을 실제 입력으로 선택했다.

```text

```

구체적인 수행 범위는 notebook의 실제 입력을 추적하고, 공통 날짜·scaled SMAP·
ACC·ubRMSE·screening·월별 집계를 점검하는 것이다. 연구 README와
대상 METHODS 문서를 읽었으며 기존 notebook과 원자료는 변경하지 않았다.

### 2.2 수행 결과와 근거

CSV끼리만 비교하지 않고, daily 물리값 cache에서 별도의 구현으로
climatology와 월별 지표를 재계산했다. 대상 표에는 2015–2025년의
관측일 지점·연도·월 조합 20,401개가 있다. 수치 일치 여부와 최대 차이는
아래 audit.json을 최종 근거로 한다.

실행은 정상 종료했으며 최대 절대 차이는 ACC 8.07 × 10^-14,
ubRMSE 9.97 × 10^-17, 최종 집계값 3.33 × 10^-16이었다.
수치 불일치는 발견되지 않았고, 검사한 원본 파일의 SHA-256도 변하지 않았다.

기본 표본은 All 356개, filtered 312개지만 월별 유효 지점 수는
All 173–349개, filtered 153–306개로 달랐다. 또한 공통 SMAP 선은
DA_single의 scaled daily 관측이다. 이 두 사항은 오류로 단정할 것이 아니라
표본·자료 정의와 해석 한계로 명시해야 한다.

- [실제 작업 결과와 점검표](step2_audit_20261019/RESULTS_KO.md)
- [실행한 점검 코드](step2_audit_20261019/audit_comparison.py)
- [수치 검증 및 파일 보존 기록](step2_audit_20261019/audit.json)
- [이번 작업에서 추출한 Skill 초안](step2_audit_20261019/SKILL_DRAFT.md)

이번 범위는 daily cache에서의 수치 재현이다. 위성 원자료와 DAOBS를 전부
재독해 cache를 다시 만들지는 않았으므로 원자료 처리 전체의 정확성까지
검증했다고 쓰지 않는다. 기존 실행 notebook의 오류 출력을 점검했고,
plotting notebook 전체 재실행 대신 수치 재계산 스크립트를 실행했다.

### 2.3 고쳐 달라고 한 내용

최초 결과 제시 후 사용자는 “지금 고칠 점이 있나 ? 뭐 한줄을 고치고.
제출 보고서에 넣으라고 했잖아”라고 요청했다. 이에 따라 실제 점검에서
발견한 월별 표본 변화에 관한 절차 한 줄을 수정했다. 수정 문장과 이유는
5절에 기록했다. 과거 대화에서의
scaled SMAP 사용, climatological 31-day mean, 동일 날짜 비교,
저장된 점수만 믿지 않는 독립 재계산 요청을 이미 알려진 요구사항으로 적용했다.
이 과거 요청을 이번 단계에서 새로 받은 피드백으로 기재하지 않는다.

이번 요청은 한 줄 수정 및 보고서 기록에 관한 실제 피드백이다.
다만 사용자가 수정된 초안 전체를 직접 검토했거나 최종 승인했다고

### 6.2 공개 범위와 이력 보존

사용자가 기존 GitHub 저장소 안에 MMDA 폴더를 만들도록 확정했다.
현재 연구 브랜치에는 과제와 무관한 연구 commit이 있어 그대로 push하지 않고,
`origin/main` 기준의 별도 `assignment-mmda-20261019` 브랜치에
`MMDA/` 아래의 문서와 Skill만 추가한다. main이나 기존 연구 브랜치를
force-push하거나 변경하지 않는다. 새 GitHub 저장소를 만들지는 않는다.

수정 전 원래 로컬 기준 commit은 `c99e6483ab4e2c7f1160c8310f0fd1ebff66e4f6`이다.
이 commit의 다른 연구 조상 commit까지 공개하지 않기 위해,
동일한 수정 전 Skill 두 파일만 MMDA 경로에 별도 commit으로 보존했다.
공개 브랜치의 수정 전 commit은 `0244d65`이며 그 위에 수정 후 Skill과
보고서·시험 근거를 별도로 commit한다. 두 Skill 사이의 변경은 출력 순서
한 줄뿐이다. 이력 확인 방법은 MMDA/SUBMISSION_GIT.md에 기록한다.

공개 파일은 `MMDA/.agents/skills/audit-da-comparison/`와 본 과제의 보고서·시험 근거,
사용자가 요청한 MMDA 관련 README 사본이다. 보고서 안의 `.agents/skills/`
경로는 과제 수행 시 원래 연구 저장소의 경로이며, 공개본은 그 앞에 MMDA/가 붙는다.
LIS/LDT 코드, 실제 모델 output, ISMN 및 위성 원자료, daily cache와 그림 전체는
새 변경으로 포함하지 않는다. 원격 main에 이미 있는 파일은 그대로 남는다.
공개된 감사 스크립트와 hash는 수행 근거이며, 업로드하지 않은 로컬 자료가
없어도 전체 연구를 재실행할 수 있는 독립 패키지라는 의미는 아니다.
